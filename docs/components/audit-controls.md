# Audit & SOX Controls Component Deep Dive

The Audit and SOX Controls subsystem provides institutional compliance, cryptographic provenance, and immutable event logging to satisfy internal and external auditors (e.g. Sarbanes-Oxley Section 404).

---

## 1. Package Structure

Located at [`backend/app/audit/`](../../backend/app/audit/):

```
app/audit/
├── __init__.py
├── controls.py     # Deterministic SOX control registry & mapping catalog

```

## 2. The Deterministic SOX Control Catalog

Vexa maps exceptions, close tasks, and system events to recognized accounting controls deterministically via [`map_to_control_id`](../../backend/app/audit/controls.py#L73). Control IDs are **never generated by an LLM**:

| Control ID | Control Name | Primary Exception & Task Mappings |
| :--- | :--- | :--- |
| **`AP-03`** | Duplicate Payment & Invoice Prevention | `DUPLICATE_PAYMENT`, `DUPLICATE_INVOICE`, `PAYMENT_FRAGMENTATION`, `AP_RECONCILIATION`, `PAYMENT_RECONCILIATION` |
| **`AP-07`** | Vendor Master Bank Account Modification | `VENDOR_BANK_CHANGE_ANOMALY`, `UNUSUAL_VENDOR_ACTIVITY` |
| **`PROC-04`**| 3-Way Procurement Matching Control | `PO_MISMATCH`, `RECEIPT_MISMATCH`, `MISSING_DOCUMENT`, `INVOICE_VALIDATION` |
| **`GL-02`** | General Ledger Mapping & Balance Control | `GL_MAPPING_ERROR` |
| **`BANK-01`**| Bank Reconciliation Control | `BANK_GL_MISMATCH`, `CASH_ANOMALY`, `PAYMENT_MISMATCH`, `BANK_RECONCILIATION` |
| **`CLOSE-01`**| Period-End Close Completeness Control | `DATA_INGESTION_GAP`, `EXCEPTION_REVIEW`, `FINAL_VERIFICATION`, `CLOSE_PACKAGE` |
| **`REV-01`** | Accounts Receivable Remittance Matching | `AR_MISMATCH`, `AR_RECONCILIATION` |
| **`EXP-01`** | Accrued Liabilities & Expense Anomaly | `ACCRUAL_ANOMALY`, `VARIANCE_ANALYSIS`, `ACCRUAL_REVIEW` |

## 3. Immutable Audit Event Schema

Every audit record in PostgreSQL table `audit_events` carries full contextual provenance:

```python
# app/db/models/audit.py
class AuditEvent(Base):
    id: uuid.UUID                  # Unique event ID
    company_id: uuid.UUID          # Tenant boundary foreign key
    close_run_id: uuid.UUID | None # Associated close run (if applicable)
    exception_id: uuid.UUID | None # Associated exception (if applicable)
    event_type: AuditEventType     # High-level category (e.g. EXCEPTION_DECISION, APPROVAL, REVERSAL)
    actor: str                     # Human user ID or agent identifier
    actor_type: str                # "user" | "agent" | "system" | "CONTROLLER"
    agent_name: str | None         # "cfo_investigation_agent", "close_controller", etc.
    prompt_version_id: str | None  # Version of prompt used (e.g. "investigator-v3")
    policy_version_id: str | None  # Version of policy active (e.g. "policy-v1")
    control_id: str | None         # Deterministic SOX control ID (e.g. "AP-03", "PROC-04")
    decision: str | None           # Decision taken (e.g. "AUTO_RESOLVE", "STAGE", "CLOSED")
    reason: str | None             # Technical explanation or human review notes
    financial_impact: Decimal      # Recalculated monetary impact
    currency: str                  # Base currency (e.g. "USD", "INR")
    confidence: Decimal | None     # Raw model confidence
    calibrated_confidence: Decimal # Calibrated empirical confidence
    evidence_ids: list[str]        # Cited primary record and graph node IDs
    metadata_json: str | None      # Additional payload attributes
    created_at: datetime           # UTC timestamp
```

### Reproducibility Guarantee
Because each audit event records `prompt_version_id`, `policy_version_id`, and exact `evidence_ids`, historical decisions can be independently verified and reproduced against the exact prompt and policy versions that produced them.
